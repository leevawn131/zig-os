## Context
[ADR-0003](0003-limine-gdt-preservation-phase1.md) originally retained Limine 12.9.6's bootloader Global Descriptor Table (GDT) (`CS = 0x28`, `DS = SS = 0x30`) throughout Phase 1 and deferred custom GDT, 64-bit Task State Segment (TSS), and Interrupt Stack Table (IST) initialization to Phase 2, leaving `ist = 0` on all 256 Interrupt Descriptor Table (IDT) gates.

Independent architectural audit (Finding `F-04`) established four technical requirements for Phase 1 hardening on the **Bootstrap Processor (BSP)**:
1. **Minimize the `IDTR = undefined` Window at Entry**: Per the Limine Boot Protocol (*Entry / Machine State — x86_64*), `GDTR` is valid at `_start()` entry (`0x28` 64-bit code, `0x30` 64-bit data), whereas `IDTR` is `undefined`. Furthermore, under Limine Base Revision 3, masking of IOAPIC `NMI` and `ExtINT` delivery modes is not guaranteed by the protocol (guaranteed only from Base Revision 5+). While the finite window between bootloader entry and the first `lidt` instruction cannot be completely eliminated in software, installing an initial 256-gate IDT (`ist = 0`) immediately after `cpu.cli()` reduces that window to the minimum possible instruction span.
2. **Stack-Overflow Double Fault Mitigation (`IST1`)**: With `ist = 0` on Vector 8 (`#DF` Double Fault), a Ring 0 kernel stack overflow into an unmapped page faults while delivering the initial `#PF` and faults again while attempting to push the `#DF` frame onto the same invalid `%rsp`, escalating into an undiagnosable Triple Fault. Assigning a dedicated `IST1` stack to Vector 8 mitigates the stack-overflow path to Triple Fault by switching `%rsp` to a known-mapped emergency stack before pushing the `#DF` frame.
3. **Asynchronous NMI (`IST2`) and Machine Check (`#MC`, Vector 18, `IST3`) Isolation (`MCE-2`)**: Under Limine Base Revision 3, zeroing of unspecified `CR4` bits is only guaranteed starting from Base Revision 5, and `cpu.enableSse()` (`computeSseCr4()`) preserves all pre-existing `CR4` bits other than `OSFXSR` and `OSXMMEXCPT`. Under policy `MCE-2`, the Phase 1 kernel preserves the `CR4.MCE` (bit 6) state handed off by Limine without proactively clearing or setting `CR4.MCE`, and unconditionally provisions `IST3` (`16 KiB`) for IDT Vector 18 (`#MC`, `idt_table[18].ist = 3`) alongside `IST1` for Vector 8 (`#DF`) and `IST2` for Vector 2 (`#NMI`). If `CR4.MCE == 1` and hardware delivers `#MC` via Vector 18, the handler executes on `IST3`; if `CR4.MCE == 0`, provisioning `IST3` does not automatically enable `#MC` delivery, and `MCE-2` does not eliminate all hardware CPU Shutdown conditions caused by Machine Check errors.
4. **Bootloader GDT Independence**: Limine places its initial GDT in `.bootloader_reclaimable` memory and does not provide a kernel-usable TSS or Task Register (`TR`) configuration.

## Decision
1. **Supersede ADR-0003 (Single Bootstrap Processor Scope & Hardware-Independent Model Separation)**:
   - Establish a kernel-owned 64-bit GDT, a 64-bit TSS (`Tss64`, `104` bytes), and three dedicated 16 KiB IST stacks in writable kernel `.data`/`.bss` during Phase 1 early boot.
   - **Processor Scope**: This Phase 1 architecture applies strictly to the single **Bootstrap Processor (BSP)**. Per-CPU GDT, TSS, and IST instantiation for Application Processors (APs) is out of scope for Phase 1.
   - **Pure Model Module Separation (`gdt_model.zig`)**: Place all hardware-independent GDT/TSS structures, constants, descriptor encoders, and validators (`GdtDescriptor`, `Tss64`, `TssDescriptor16`, `encodeTssDescriptor`, descriptor access/busy checks) in `kernel/src/arch/x86_64/gdt/gdt_model.zig` with zero privileged inline assembly. This ensures host unit tests (`zig build test`, compiled by Zig 0.17.1's default self-hosted backend) never analyze privileged instructions (`sgdt`/`lgdt`/`ltr`/`str`) that require LLVM (`use_llvm = true` in `build.zig`).
2. **Explicit Separation of 10-Byte `GDTR` Operand, 16-Byte TSS Descriptor, and 104-Byte `Tss64` Structure**:
   - **10-Byte `GDTR` Memory Operand (`lgdt`/`sgdt`)**: Defined as `extern struct { limit: u16, base: u64 align(1) }` (`@sizeOf(GdtDescriptor) == 10`, `@offsetOf(limit) == 0`, `@offsetOf(base) == 2`) so its ABI byte size matches the exact 10-byte (80-bit) hardware `GDTR` pseudo-descriptor without trailing padding.
   - **GDT Table Layout (`11 * 8 = 88` bytes, `GDTR.limit = 87 = 0x57`, writable `.data`/`.bss`, `align(16)`)**:
     - `0x00` (Index `0`): Null descriptor (`0x0000_0000_0000_0000`)
     - `0x08..0x20` (Indices `1..4`): Reserved descriptors (`0x0000_0000_0000_0000`, Not-Present)
     - `0x28` (Index `5`, `KERNEL_CODE_SELECTOR`): 64-bit Kernel Code (`DPL = 0`, `L = 1`, `D = 0`, initial Access `0x9A`, Flags `0x2` -> `0x0020_9A00_0000_0000`). **Owner-Approved Option A CS Accessed-Bit Policy**: Post-load validation accepts both `0x9A` (Accessed bit clear) and `0x9B` (Accessed bit set), ignoring **only** bit 40 (`DESCRIPTOR_ACCESSED_BIT`) during structural comparison while requiring every other descriptor bit to match `KERNEL_CODE_DESCRIPTOR` exactly. This accommodates observed **QEMU TCG 10.2.1** behavior, where `lretq` did not write back the Accessed bit; this ADR does **not** claim that all physical CPUs or hypervisors exhibit QEMU TCG behavior. The `Accessed` bit is **not** used as a security or privilege invariant in this Phase 1 validator.
     - `0x30` (Index `6`, `KERNEL_DATA_SELECTOR`): 64-bit Kernel Data (`DPL = 0`, `W = 1`, initial Access `0x92`, Flags `0x0` -> `0x0000_9200_0000_0000`; CPU hardware sets Accessed bit 40 upon segment reload -> Access `0x93`; **strict `0x93` post-load validation requirement preserved** and not weakened by Option A)
     - `0x38` (Index `7`): Reserved (`0x0000_0000_0000_0000`, Not-Present in Phase 1; reserved for 64-bit User Data in Phase 2)
     - `0x40` (Index `8`): Reserved (`0x0000_0000_0000_0000`, Not-Present in Phase 1; reserved for 64-bit User Code in Phase 2)
     - `0x48..0x57` (Indices `9..10`, `TSS_SELECTOR = 0x48`): **16-Byte 64-Bit TSS System Descriptor** occupying two consecutive 8-byte GDT slots (`DPL = 0`, `Limit = 0x0067` [`103`], initial Type `0x9` Available 64-bit TSS = Access `0x89` prior to `ltr`; hardware atomically sets Busy bit 41 to Type `0xB` / Access `0x8B` upon `ltr`; **strict `0x8B` Busy post-load validation requirement preserved** and not weakened by Option A; upper 32 bits `127:96` strictly `0`).
   - **104-Byte `Tss64` Structure (`@sizeOf(Tss64) == 104`, `0x68` bytes)**: `extern struct` with `align(1)` on all 4-byte-offset `u64` fields (`rsp0` at `0x04`, `ist1` at `0x24`, `ist2` at `0x2C`, `ist3` at `0x34`, `iomap_base = 104` at `0x66`), placed in permanently mapped `.bss` (`align(16)` as a kernel design choice).
3. **Eight-Step Ordered Early Boot Sequence in `_start()` (`RFLAGS.IF = 0` Maintained Throughout)**:
   - **Step 1 — Disable Maskable Interrupts (`cpu.cli()`)**: Clear `RFLAGS.IF` immediately at `_start()`.
   - **Step 2 — Early IDT Installation (`idt.initEarly()`, `ist = 0`)**: Immediately after `cpu.cli()` (prior to `cpu.enableSse()`, `serial.init()`, and `pic.remapAndMask()`), populate all 256 IDT gates (`0x8E`) using Limine's active `0x28` code selector (`gdt.getCs()`) with `ist = 0` on all 256 gates, and execute `lidt(&idtr)`.
     - *Pre-SSE Execution Safety Proof*: Because the freestanding kernel target disables `.x87`, `.mmx`, `.sse`, `.sse2`, `.avx`, and `.avx2` and enables `.soft_float` (`F-01`, verified via `objdump -d` to emit zero SIMD/x87 instructions across `kernel.elf`), `idt.initEarly()`, `isr_stub_0..255`, `isr_common`, and the pre-serial emergency path in `x86_64_interrupt_dispatch()` execute strictly integer GPR instructions and cannot fault on `CR0.EM`/`CR0.TS` prior to `cpu.enableSse()`.
   - **Step 3 — FPU/SSE Control Register Initialization (`cpu.enableSse()`)**: Clear `CR0.EM` and `CR0.TS`, set `CR0.MP`, and set `CR4.OSFXSR` and `CR4.OSXMMEXCPT` while preserving the `CR4.MCE` bit handed off by Limine (`MCE-2`).
   - **Step 4 — COM1 UART Initialization (`serial.init()`)**: Initialize COM1 (16550 UART) and set `serial.initialized = true` upon loopback verification (or halt immediately in `cpu.haltLoop()` on failure).
   - **Step 5 — Early Platform, SSE Self-Test, and Legacy 8259 PIC Remap/Mask**: Verify `limine.isBaseRevisionSupported()`, run `cpu.testSseCr0Init()`, verify `limine.memmap_request.response`, and execute `pic.remapAndMask()` (remapping master/slave 8259 PICs to `0x20–0x2F` and masking all 16 IRQ lines `0xFF`/`0xFF`).
   - **Step 6 — One-Shot Kernel GDT & TSS Initialization (`gdt.init()` & `gdt.testGdtAndTss()`)**:
     - `gdt.init()` enforces a strict **one-shot** lifecycle contract via a module-level `initialized` guard (`if (initialized) @panic(...)`) and **never resets an active Busy bit (`0x8B -> 0x89`) to fake idempotency**.
     - Initialize `kernel_tss` with three distinct, 16-byte-aligned 16 KiB static `.bss` stacks: `ist1_stack` (`kernel_tss.ist1` -> Vector 8 `#DF`), `ist2_stack` (`kernel_tss.ist2` -> Vector 2 `#NMI`), and `ist3_stack` (`kernel_tss.ist3` -> Vector 18 `#MC` under `MCE-2`).
     - Encode the initial Available 16-byte TSS descriptor (`Access = 0x89`) into `gdt_table[9..11]`, execute `lgdt(&gdtr)` + `%cs` reload (`0x28` via `lretq`) + `%ds`/`%es`/`%ss` reload (`0x30`) + visible `%fs`/`%gs` selector load (`0x0000` via `movw $0x00, %ax` with explicit `.{ .rax = true, .memory = true }` clobbers), and then invoke **`cpu.ltr(gdt_model.TSS_SELECTOR)` (`0x48`) as a separate call after `lretq`** so register allocation cannot alias `[tss_sel]` with clobbered `%rax`.
     - `gdt.testGdtAndTss()` verifies `sgdt` (10-byte `GdtDescriptor`), `str() == 0x48`, `gdt_table[5]` under Option A (`isCodeDescriptorValidPostLoad`: accepts both `0x9A` and `0x9B`, ignoring only bit 40 while matching every other bit of `KERNEL_CODE_DESCRIPTOR` exactly), strict hardware-set Accessed bit on `gdt_table[6]` (`0x93`), strict hardware-set Busy bit on `gdt_table[9]` (`0x8B`), active selectors `CS == 0x28` / `DS == SS == 0x30`, and three disjoint 16-byte-aligned IST stacks (verified without wrapping address additions).
     - *Vendor-Dependent `FS`/`GS` Null Selector Semantics*: Per AMD64 APM Vol. 2 §4.5.3, loading a null selector into `FS`/`GS` does not modify the hidden `FS.base`/`GS.base` register, whereas on Intel 64 processors (Intel SDM Vol. 3A §3.4.4, verified empirically by Linux) it clears the hidden base to `0`. Because Limine guarantees `FS.base = 0` and `GS.base = 0` at entry, both architectures remain at base `0` in Phase 1; however, loading a null selector must never be used as a portable mechanism to clear or preserve `FS.base`/`GS.base`.
     - *NMI Transition Safety*: Because `0x28` and `0x30` match Limine's selectors and all IDT gates still have `ist = 0` throughout `gdt.init()`, any `#NMI` arriving during the GDT/TSS transition executes safely on the current stack without referencing `TR` prior to `ltr`.
   - **Step 7 — IST Stack-Switch Verification, Ordered IST Gate Activation, & IDT Self-Tests**:
     - Run `idt.testExceptionDispatch()` (`ist = 0`) and `idt.testIstStackSwitch()` (exercising `idt_table[3].ist` = `1, 2, 3` via `int $3` and restoring `0`) **prior to `idt.enableIstGates()`**, while `TR` and `TSS.IST1..IST3` are live from Step 6 and `idt_table[2/8/18].ist` remain `0` (eliminating theoretical `IST2` re-entrancy collisions with asynchronous `#NMI` during `test_ist == 2`).
     - Execute `idt.enableIstGates()` to activate `IST1`, `IST2`, and `IST3` via **ordered per-entry IDT updates** (not a single atomic multi-entry transaction) while `RFLAGS.IF = 0`: setting `idt_table[8].ist = 1` (`#DF` -> `IST1`), `idt_table[2].ist = 2` (`#NMI` -> `IST2`), and `idt_table[18].ist = 3` (`#MC` -> `IST3`), leaving all other 253 gates at `ist = 0`. Because `kernel_tss` and all three IST stacks are already fully provisioned in Step 6 prior to modifying IDT entries, and because `CLI` masks maskable interrupts but does **not** mask `#NMI` or `#MC`, an `#NMI` or `#MC` arriving during the transition window may observe either the old valid (`ist = 0`) gate configuration or the newly activated IST gate configuration for its corresponding vector; both the early handling path and the activated IST handling path remain valid throughout the transition window.
     - Run `idt.validateExceptionGates()` (verifying final production gate state across all 256 entries) and `idt.testPageFaultHandling()`, emitting the exact marker `[IDT] 256 interrupt gates configured and verified.`.
   - **Step 8 — Memory Subsystems (`PMM`, `VMM`, `Heap`) & Quiescent Halt (or Isolated Standalone `#DF` Test)**:
     - **Step 8.1**: Initialize and self-test PMM (`pmm.init()`, `pmm.testPmm()`).
     - **Step 8.2**: Self-test VMM (`vmm.testVmm()`).
     - **Step 8.3**: Initialize and self-test Heap (`heap.init(4)`, `heap.testHeap()`).
     - **Step 8.4**: In the production build subgraph (`kernel_mod`, `build_options.test_double_fault == false`, output `zig-out/bin/kernel.elf` & `build/zig-os.iso`), emit `[STATUS] Kernel initialization complete.` and `zig-os:~$ ` and enter `cpu.haltLoop()`. In the completely isolated DF-test build subgraph (`df_kernel_mod`, `build_options.test_double_fault == true`, output `zig-out/df-test/kernel-df-test.elf` & `build/zig-os-df-test.iso`, invoked only via `zig build test-df`), invoke `idt.runStandaloneDoubleFaultTest()` (`noreturn`) immediately after Step 8.3.
4. **Pre-Serial and Bounded-Polling Emergency Exception & Panic Logging (`handlers.zig`, `panic.zig`, `serial.zig`)**:
   - If an unhandled exception or `#NMI` occurs while `serial.initialized == false` (including the pre-SSE window between Steps 2 and 4), `x86_64_interrupt_dispatch()` must skip UART logging altogether and immediately enter `cpu.haltLoop()` (`cli; hlt`).
   - When `serial.initialized == true`, both fatal exception logging (`handlers.logException()`) and kernel panic logging (`panic.panicFn()` in `kernel/src/panic.zig`) must use bounded UART transmit-ready polling (`MAX_TX_POLL_SPINS` per byte) without re-invoking `serial.init()` on each character; if `serial.init()` fails in `panicFn()` or the UART fails to respond within the spin bound, logging aborts immediately and execution enters `cpu.haltLoop()`.
5. **Double Fault Architectural Non-Restartability and Phase 1 Machine Check Kernel Policy**:
   - **Double Fault (`#DF`, Vector 8 — Architectural Non-Restartable Abort)**: Per Intel SDM Vol. 3A §6.15, `#DF` is an Abort exception whose saved `CS:RIP` is architecturally undefined for resumption. The `#DF` handler must never attempt recovery or execute `IRETQ`; it must perform bounded-polling serial logging on `IST1` (when `serial.initialized == true`) and halt in `cpu.haltLoop()`.
   - **Machine Check Exception (`#MC`, Vector 18 — Phase 1 Kernel Policy)**: Although the x86-64 Machine Check Architecture (MCA, Intel SDM Vol. 3A Chapter 16) provides hardware status registers and flags (`IA32_MCG_STATUS.RIPV`/`EIPV`/`MCIP`, `IA32_MCi_STATUS.PCC`/`UC`) that allow software to determine recoverability on supported processors, ZIG-OS Phase 1 does not implement an MCA status parser. Therefore, as a **Phase 1 Kernel Policy**, `#MC` is treated as strictly terminal: the handler on `IST3` must never attempt recovery or execute `IRETQ`, must perform bounded-polling serial logging when `serial.initialized == true`, and must halt safely in `cpu.haltLoop()`.
6. **Phase 1 Boundary & Bootloader Memory Preservation**:
   - Phase 1: F-04 implementation completed by Gemini 4 Hydrogen, pending independent GPT-6 review and Project Owner acceptance (`Pending Human Review`). Phase 2 remains `NOT AUTHORIZED`.
   - Ring 3 execution, `SYSCALL`/`SYSRET`, and scheduling remain deferred to Phase 2.
   - `.bootloader_reclaimable` memory remains reserved (`USED`) in the PMM because active page tables (`CR3`), the initial 64 KiB stack (`%rsp`), and `limine_region_ctx` memory-map entries still reside in `.bootloader_reclaimable` frames.

## Alternatives Considered
1. **Retain ADR-0003 Until Phase 2**: Rejected because it leaves `F-04` unresolved and leaves Ring 0 stack-overflow faults without an emergency `#DF` stack.
2. **Run `gdt.init()` or `serial.init()` Before `idt.initEarly()`**: Rejected because Limine hands off `IDTR` as `undefined` while already providing a valid `0x28`/`0x30` GDT; installing the initial IDT (`ist = 0`) immediately after `cpu.cli()` minimizes the `IDTR = undefined` window.
3. **Clear `CR4.MCE` Instead of Allocating `IST3` (`MCE-1`)**: Rejected because clearing `CR4.MCE = 0` forces any hardware machine check into an immediate unlogged CPU Shutdown state instead of routing through Vector 18 when `CR4.MCE == 1`.
4. **Reset Busy Bit in `gdt.init()` to Simulate Idempotency**: Rejected because `gdt.init()` is a strict BSP one-shot initialization; clearing the hardware Busy bit on an active TSS masks initialization lifecycle bugs.
5. **Single Boolean `df_test_armed` or Non-CAS Load/Store for Standalone `#DF` Test**: Rejected because `cli` does not mask `#NMI` (Vector 2) or `#MC` (Vector 18); only an atomic CAS (`cmpxchgStrong`) state machine with immutable terminal states cleanly separates asynchronous `#NMI`/`#MC` (including during `.handling_df`), nested synchronous faults, and late post-`PASS` arrivals.
6. **Mutating Production `kernel_mod` via `-Dtest-double-fault=true` Overwriting `zig-out/bin/kernel.elf` / `build/zig-os.iso`**: Rejected because it risks contaminating production ELF, ISO staging root, ISO image, and `F-14` provenance metadata; two independent `build.zig` subgraphs with disjoint artifact paths guarantee structural isolation.

## Consequences
### Positive
- Minimizes the early-boot `IDTR = undefined` window by installing `idt.initEarly()` (`ist = 0`) immediately after `cpu.cli()`.
- Guarantees bounded-time, busy-wait-free `cpu.haltLoop()` termination across both fatal exceptions and panics even if COM1 is uninitialized or unresponsive.
- Mitigates the stack-overflow path to Triple Fault by routing `#DF` (Vector 8) to `IST1` (while recognizing that other causes such as `IST1` exhaustion or corrupted page/descriptor tables can still cause a Triple Fault).
- Isolates `#NMI` (Vector 2 -> `IST2`) and `#MC` (Vector 18 -> `IST3` when `CR4.MCE == 1`) onto independent emergency stacks with zero race window during `gdt.init()` or `idt.testIstStackSwitch()`.
- Keeps production build outputs (`zig-out/bin/kernel.elf`, `build/iso_root`, `build/zig-os.iso`) structurally isolated from standalone DF-test outputs (`zig-out/df-test/kernel-df-test.elf`, `build/df-test/iso_root`, `build/zig-os-df-test.iso`).
### Negative / Trade-offs
- Reserves 48 KiB of static `.bss` memory on the BSP (`16 KiB` each for `IST1`, `IST2`, and `IST3`).

## Security Implications
- Enforces `DPL = 0` on the 16-byte 64-bit TSS descriptor (`0x89`/`0x8B`) and disables the I/O permission bitmap (`iomap_base = 104`).
- Keeps Ring 3 GDT slots (`0x38`, `0x40`) unpopulated (`Not-Present`) throughout Phase 1.
- Links `df_trigger.s` exclusively into the isolated DF-test executable (`zig-out/df-test/kernel-df-test.elf`) and structurally excludes it from production `zig-out/bin/kernel.elf`.
- Eliminates integer wrap-around and zero-length edge-case risks in stack/frame range checks by rejecting `frame_size == 0` in both `isFrameWithinStack` and `isFrameDisjointFromStack` and using checked arithmetic (`std.math.add`) / remaining-bytes subtraction with fail-closed overflow rejection.
- **CS Accessed Bit Is Not a Security or Privilege Invariant (Option A)**: Bit 40 (`DESCRIPTOR_ACCESSED_BIT`) on the kernel code descriptor (`0x28`) is explicitly **not** used as a security or privilege invariant in the Phase 1 post-load validator. Every other descriptor bit (including `P=1`, `DPL=0`, `S=1`, `Type=0xA`, `L=1`, `D=0`) must still match `KERNEL_CODE_DESCRIPTOR` strictly, and strict `DS`/`SS` (`0x93`) and Busy TSS (`0x8B`) validation remains unchanged.
